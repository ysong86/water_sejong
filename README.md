# 세종시 물환경 상황판

세종 구간의 **하천 수위 · 강수량 · 실시간 수질 · 지하수 · 기상**을 한 화면으로 모으는
로컬 상황판. 표준 라이브러리만 쓰고, 결과물은 자기완결형 `dashboard.html` 한 장이다.

물환경 밖의 블록도 같은 화면에 함께 둔다 — **안심의료**, **자족도시 지표**,
수질오염원 통계가 그것이다. 갱신 주기가 제각각이라 블록마다 관측시각 또는
기준연도를 밝힌다.

## 빠른 시작

키 없이 화면부터 보기 (샘플 데이터):

```bash
C:/Python313/python.exe run.py --demo --open
```

실측 연동:

```bash
C:/Python313/python.exe run.py --collect --open
```

## 화면 구성

- **관측시각 줄** — 소스별 최신 관측시각과 경과 시간. 기준을 넘기면 주황으로 바뀐다.
  API 응답에 담긴 **관측시각**이지 수집 시각이 아니다.
- **상단 KPI** — 하천 최고 홍수단계 / 24h 누적 강수 / 수질 최저 등급 / 24h 예보 강수 /
  지하수위 24h 변화
- **지점 탐색 (좌–중–우)**
  - 좌: 하천 수위 · 강수량 · 수질 · 지하수로 묶인 관측지점 목록
  - 중앙: 세종시 지도. 마커 모양은 종류(▲ 수위 / ■ 강수 / ● 수질 / ◆ 지하수), 색은 상태
  - 우: 선택 지점 상세 — 수위는 홍수단계 게이지와 24h 추이, 강수는 시간별 분포,
    수질은 항목별 수치, 지하수는 수위·수온·EC
  - 목록·지도 어느 쪽을 눌러도 셋이 함께 움직인다
- **실시간 수질 전 지점** — 모든 지점을 한 표에서 비교
- **기상** — 초단기실황 + 24h 강수량·강수확률 예보, 기상특보
- **안심의료** — 응급실 실시간 가용병상, 지금 문 연 약국·소아청소년과
  ([아래](#안심의료-365-24) 참고)
- **자족도시 지표** — 통근·일자리로 본 자족성 다섯 지표. 연 단위라 실시간이 아니다
  ([아래](#자족도시-지표) 참고)

### 지도 조작

| 동작 | 결과 |
|---|---|
| 지도 위에서 휠 | 커서 지점을 중심으로 확대·축소 (최대 14배) |
| 끌기 | 이동 |
| 더블클릭 | 그 지점으로 확대 |
| `+` `−` `초기화` | 중앙 기준 확대·축소·복귀 |
| 하천에 커서 | 선이 굵어지고 하천 이름 표시 |
| 관측지점에 커서 | 지점 이름 표시 (선택한 지점은 계속 표시) |

확대해도 글자와 마커 크기, 선 굵기는 그대로 유지된다(역보정).

### 소스별 갱신 주기

기관이 실제로 갱신하는 주기가 다르다. 아무리 자주 수집해도 이보다 빨라지지 않는다.

| 소스 | 원 제공주기 | 비고 |
|---|---|---|
| 하천 수위·강수 (HRFCO) | **10분** | `hrfco.time_type` 기본 `10M`. 금강권역은 관측 후 11분 이상 걸려 관측소별 최신시각이 조금씩 다르다 |
| 실시간 수질 (NIER) | 1시간 | 자동측정망 |
| 지하수 (GIMS) | 1시간 | 시간자료 |
| 기상 초단기실황 (KMA) | 1시간 | 매시 정시 자료가 +40분경 배포. 그래서 화면에 늘 30~60분 전으로 뜬다 |
| 응급실 가용병상 (국립중앙의료원) | **수시** | 기관이 직접 입력한다. 30분을 넘기면 관측시각 줄이 주황으로 바뀐다 |
| 자족도시 지표 | **5년 / 1년** | 통근통학은 인구주택총조사 5년 주기, 종사자수는 전국사업체조사 연 1회. API 를 쓰지 않고 사람이 파일에 적는다 |

관측시각 줄의 색은 이 주기를 기준으로 판정한다(하천·강수 30분, 수질 3시간,
지하수 4시간, 기상 2시간을 넘기면 주황). 칩에 커서를 올리면 원 제공주기가 뜬다.

## 배포 — 다른 사람이 보게 하기

**수집·생성은 이 PC 에서, GitHub 은 서빙만 한다.**

처음엔 GitHub Actions 로 전부 돌리려 했으나 **한강홍수통제소 API 가 해외 IP 에
응답하지 않는다**(거부가 아니라 타임아웃). GitHub 러너는 해외에 있어 수위·강수를
못 받는다. 같은 키가 국내 PC 에서는 정상 작동한다. 그래서 구조를 이렇게 바꿨다.

```
이 PC (국내 IP)                          GitHub
  run.py --collect  ── API 호출 ─┐
  build_dashboard   ── HTML 생성 ─┴─► gh-pages 브랜치 ─► Pages 가 서빙
```

### 한 번만 하는 설정

1. GitHub 저장소 Settings → Pages → Source 를 **`Deploy from a branch`**,
   Branch 를 **`gh-pages` / `(root)`** 로 지정한다.
2. 자동 실행 등록:

```bash
powershell -ExecutionPolicy Bypass -File tools
egister_task.ps1
```

10분 간격으로 `tools\publish.ps1` 이 돈다. 해제는 `-Remove` 를 붙인다.

### 수동 배포

```bash
powershell -ExecutionPolicy Bypass -File tools\publish.ps1
```

수집 → `site\index.html` 생성 → `gh-pages` 브랜치로 force push 까지 한 번에 한다.
gh-pages 에는 **커밋 하나만** 두고 매번 덮어쓴다(amend). 매 실행마다 커밋을 쌓으면
37KB × 하루 144회 = 한 달 160MB 로 불어나기 때문이다.

### 한계

- **이 PC 가 켜져 있어야 갱신된다.** 클라우드로 옮길 수 없는 이유는 위와 같다.
  꺼져 있어도 사이트는 계속 열리며, 마지막 관측시각이 화면에 그대로 표시되므로
  자료가 오래됐다는 사실은 보는 사람이 알 수 있다.
- 노트북이면 절전 상태에서 작업이 밀린다. 작업 스케줄러에 `StartWhenAvailable`
  을 켜 두었으므로 깨어나면 곧바로 한 번 돈다.
- 인증키는 `config.json` 에만 있고 저장소에 올라가지 않는다.

### 방문자 수 (투데이 / 토탈)

정적 페이지라 스스로 셀 수 없어 세어 주는 곳이 필요하다. `config` 의 `site.counter`
로 고른다. 기본값은 `none`(표시 안 함).

| provider | 설정 | 특징 |
|---|---|---|
| `goatcounter` | `code` (계정 코드), `path` | 가입만 하면 끝. 무료·쿠키 없음 |
| `custom` | `url` (JSON `{today,total}` 반환) | 수치를 내가 통제. 아래 워커 |
| `none` | — | 표시하지 않음 |

`custom` 용 Cloudflare Worker 를 [tools/counter-worker.js](tools/counter-worker.js) 에
넣어 두었다. 무료 한도로 충분하다. 배포 절차는 파일 첫머리 주석에 있다.

**무엇을 셀지** 는 워커의 환경변수 `COUNT_MODE` 로 고른다.

| 값 | 세는 것 | 라벨 |
|---|---|---|
| `hits` (기본) | 새로고침 포함 모든 방문 — 조회수 | 조회수 |
| `unique` | 하루에 여러 번 들어와도 1 — 순방문자 | "방문자 수" 로 되돌릴 것 |

기본이 `hits` 라 Cloudflare 에서 환경변수를 따로 넣지 않아도 된다. 화면 라벨도
`site.counter.label` 에 "조회수" 로 맞춰 두었다. `unique` 로 바꾸면
IP + User-Agent 해시로 하루짜리 표시만 남겨 중복을 걸러낸다(원본 IP 는 저장하지 않는다).

### 문의처

화면 하단에 표시된다. `site.contact` 로 바꾼다 (`org` / `name` / `title` / `email`).
공개 페이지이므로 메일 주소는 수집 봇에 노출된다는 점을 감안할 것.

## 설정

`config.example.json` → `config.json` 으로 복사한 뒤 키를 채운다.
**키가 비어 있는 소스는 조용히 건너뛰고**, 나머지 소스만으로 상황판이 만들어진다.

| 소스 | 발급처 | 비고 |
|---|---|---|
| 한강홍수통제소 (수위·강수) | <https://www.hrfco.go.kr> → 오픈API → 인증키 신청 | 공공데이터포털이 **아님** |
| 기상청 단기예보 | <https://www.data.go.kr> → "기상청 단기예보 조회서비스" | 즉시 승인 |
| 국립환경과학원 실시간 수질 | <https://www.data.go.kr> → "국립환경과학원 수질" | 승인 대기 있음 |
| 지하수 관측망 | <https://www.data.go.kr/data/15114511/openapi.do> 또는 <https://www.gims.go.kr> | 국가·지자체 관측망 |
| 응급의료기관 정보 | <https://www.data.go.kr/data/15000563/openapi.do> | 응급실 실시간 가용병상 |
| 병의원·약국 찾기 | <https://www.data.go.kr/data/15000576/openapi.do> | 진료시간(개폐 판정) |

인증키는 Encoding / Decoding 어느 쪽을 넣어도 동작한다(`%` 포함 여부로 판별).

### 관측소는 어떻게 정해지나

**하천 수위·강수** — 코드를 박아두지 않는다. 한강홍수통제소 제원 API를 받아
**주소에 `세종`이 들어가는 관측소**를 자동으로 고른다.

- `hrfco.address_keywords` — 주소 필터 (기본 `["세종"]`, `["세종","공주","청주"]` 처럼 확장 가능)
- `hrfco.waterlevel_stations` / `rainfall_stations` — 관측소 **이름**을 직접 지정하면 항상 포함
- `hrfco.max_stations` — 개수 상한 (기본 8)

**수질** — `nier.name_keywords` 로 지점명을 거른다. 좌표를 안 주는 API가 많아
지도에 찍으려면 `nier.point_coords` 에 `"지점명": [경도, 위도]` 를 넣는다.

**지하수** — `gims.stations` 에 직접 적는다. 국가관측망은 `"network":"national"`,
지자체·보조관측망은 `"local"` 로 구분해 마커 색이 달라진다.
관측소 목록과 좌표는 국가지하수정보센터(<https://www.gims.go.kr>)에서 확인한다.

**기상 격자** — `kma.lat` / `kma.lon` 에서 기상청 공식 LCC 변환식으로 계산한다
(세종시청 36.48, 127.289 → nx 66, ny 103). `nx`/`ny` 를 직접 넣으면 그 값이 우선.

### 수질·지하수 엔드포인트 확정

두 API는 공공데이터포털 상세 명세가 로그인 뒤에 있어 오퍼레이션명을 코드에 못박지
않았다. 키를 넣고 한 번 타진하면 된다:

```bash
C:/Python313/python.exe run.py --probe
```

포털 상세페이지에서 '요청주소'를 복사했다면 그것만 바로 시험하고 설정에 기록할 수 있다.
**이게 가장 확실하다** — 후보 추측을 거치지 않는다:

```bash
C:/Python313/python.exe run.py --probe --only gims --url "<복사한 요청주소>" --save
```

응답한 주소를 `nier.endpoint` / `gims.data_endpoint` 에 적어두면 이후엔 그 주소만
호출한다. 포털 상세페이지에서 '요청주소'를 직접 확인했다면 그걸 넣는 게 가장 확실하다.
한쪽만 보려면 `--probe --only gims`.

## 명령

| 명령 | 하는 일 |
|---|---|
| `--demo` | 샘플 데이터로 상황판 생성 (인수 없이 실행하면 이것) |
| `--collect` | 각 API에서 실측 수집 → `data/latest.json` 저장 → HTML 생성 |
| `--dashboard` | 재수집 없이 캐시로 HTML 만 다시 생성 |
| `--probe [--only nier\|gims\|nemc]` | 엔드포인트 후보 타진 |
| `--open` | 생성 후 브라우저로 열기 |
| `--out <디렉터리>` | 배포용으로 `<디렉터리>/index.html` 에도 저장 |
| `--config <경로>` | 다른 설정 파일 사용 |

주기 갱신은 Windows 작업 스케줄러에
`C:/Python313/pythonw.exe <이 폴더>/run.py --collect` 를 등록한다.

## 안심의료 365-24

민선 9기 공약에 '세종 365-24 안심의료체계'가 있는데, 정작 365일 24시간 무엇이
열려 있는지 보여주는 화면이 없었다. 이 블록이 그 자리를 채운다.

| 항목 | 무엇 | 성격 |
|---|---|---|
| 응급실 일반 병상 | 관내 응급의료기관의 가용/기준 병상 | **실시간** (기관 입력) |
| 지금 문 연 약국 | 신고 진료시간으로 개폐 계산 | 계산값 |
| 지금 문 연 소아청소년과 | 같은 방식. `clinic_keywords` 로 과를 고른다 | 계산값 |

세종은 출산율이 전국 최상위인데 소아 필수의료가 얇다. 소아청소년과를 따로 세우는
이유가 그것이다. `clinic_keywords` 를 `["산부인과"]` 나 `["정신건강"]` 로 바꾸면
다른 과를 볼 수 있다.

### 실측 연결하기

1. <https://www.data.go.kr> 로그인 → 아래 둘을 **활용신청**한다. 자동승인이라 보통
   몇 분 안에 쓸 수 있다.
   - `15000563` 국립중앙의료원_전국 응급의료기관 정보조회 서비스 (응급실 병상)
   - `15000576` 국립중앙의료원_전국 병의원 및 약국 찾기 서비스 (진료시간)
2. 마이페이지 → 오픈API → 인증키를 복사해 `config.json` 의 `nemc.key` 에 넣는다.
   Encoding / Decoding 어느 쪽이든 동작한다. `nier` 와 같은 계정이면 같은 키다.
3. 타진해서 필드부터 확인한다.

```bash
C:/Python313/python.exe run.py --probe --only nemc
```

   네 오퍼레이션의 응답 건수와 함께 이런 진단이 찍힌다.

```
[OK]   getEmrrmRltmUsefulSckbdInfoInqire - 3건
       · 가용 병상 필드 5개: hv6, hvec, hvgc, hvicc, hvoc
       · 기준 병상 필드 2개: hvs01, hvs02
       · 아직 짝을 안 지은 기준 필드: hvs02
       · 최신 입력시각 20260902141200 (기관 3곳)
[OK]   getParmacyListInfoInqire - 214건
       · 진료시간으로 개폐를 판정할 수 있는 곳 209 / 214
```

4. 짝을 안 지은 기준 필드가 있으면 포털 상세명세에서 뜻을 확인해 `nemc.beds` 에
   넣는다. 안 넣어도 동작하며, 그 항목은 비율 없이 가용 수만 나온다.
5. `config` 의 `site.pending` 에서 `emergency` 를 뺀다. 자료가 들어오는데도
   '업데이트 예정'으로 남아 있으면 안 된다.
6. `run.py --collect` 로 실측 확인.

**응답이 안 오면** — 이 API 는 국내 IP 에서만 확인했다. 해외 IP·클라우드에서는
막힐 수 있으니 수집 PC 에서 실행할 것. 인증키 오류는 XML(`returnAuthMsg`)로 오고,
그 문구가 화면의 **수집 경고**에 그대로 뜬다(`SERVICE_KEY_IS_NOT_REGISTERED_ERROR`
는 활용신청이 아직 승인 전이라는 뜻이다).

### 병상 필드

`hvec`(응급실 일반 가용) / `hvs01`(기준) 짝만 확실해서 이 항목만 비율과 혼잡도를
낸다. 나머지는 **가용 수만** 보여주고 색을 칠하지 않는다. 기준 병상 필드명을
확인했다면 `nemc.beds` 에 적으면 그때부터 비율이 나온다.

```bash
C:/Python313/python.exe run.py --probe --only nemc
```

응답 한 건을 통째로 찍어 주므로 거기서 필드명을 확인한다.

```json
"beds": [
  ["hvec", "hvs01", "응급실 일반"],
  ["hv6",  "hvs02", "소아 응급"]
]
```

### 전량을 받는다

세종 병의원은 한 페이지(300건)를 넘는다. 한 페이지만 받으면 「문 연 곳 18 / 전체
214」의 **분모가 조용히 잘린다.** `totalCount` 를 보고 다 받을 때까지 페이지를
넘기되, 응답이 이상해 끝나지 않는 경우에 대비해 `nemc.max_pages`(기본 12)로
상한을 둔다.

### 왜 XML 인가

`B552657` 계열은 기본이 XML 이고 서비스마다 json 지원이 들쭉날쭉하다. 응답을 받아
보고 JSON 이면 JSON 으로, 아니면 `xml.etree.ElementTree` 로 읽는다. 둘 다 표준
라이브러리다. 인증키 오류도 XML(`returnAuthMsg`)로 오므로 그 문구를 그대로 옮겨
화면의 수집 경고에 띄운다.

## 자족도시 지표

민선 9기 1호 공약이 '자족도시'인데, 자족을 무엇으로 재는지 합의된 수치가 없다.
국외에는 계보가 있다 — 영국 신도시(밀턴킨스 등) 평가에 쓰인 **자족률**
(self-containment ratio)과 미국 도시계획의 **직주균형**(jobs-housing balance).
세종은 계획신도시라 이 계보에 그대로 들어맞는다.

| 지표 | 산식 | 읽는 법 |
|---|---|---|
| 주간인구지수 | 주간인구 ÷ 상주인구 × 100 | 100 을 넘으면 낮에 사람이 들어온다 |
| 통근 자립률 | 관내거주·관내근무 ÷ 거주 취업자 × 100 | 여기 사는 사람이 여기서 일하는가 |
| 일자리 자족률 | 관내거주·관내근무 ÷ 관내 일자리 × 100 | 여기 일자리를 여기 사람이 채우는가 |
| 직주균형 | 관내 일자리 ÷ 거주 취업자 | 1.0 근처가 균형 |
| 일자리 밀도 | 관내 일자리 ÷ 상주인구 × 100 | 인구 100명당 일자리 수 |

주간인구는 따로 받지 않는다. **상주인구 − 유출통근 + 유입통근** 으로 계산한다(통계청 정의).

### 왜 API 가 아니라 파일인가

통근통학은 5년 주기, 종사자수는 연 1회다. 10분마다 부를 것이 없다. 그런데 KOSIS
통계표 ID 는 표가 개편될 때마다 바뀌어서, 코드에 박아두면 어느 해엔가 조용히 틀린
값을 그린다. 이 상황판이 가장 피하려는 실패다. 그래서 숫자는 사람이 확인해 적고,
적은 사람이 **출처와 연도를 함께 남긴다.** 그 출처가 화면에 그대로 뜬다.

### 채우는 법

```bash
copy data\selfsuff.example.json data\selfsuff.json
```

연도별로 여섯 값을 적는다. 값만 써도 되고 출처를 같이 남겨도 된다.

```json
"2020": {
  "population":         {"value": 355831, "source": "인구주택총조사 2020"},
  "employed_residents": 160000,
  "jobs":               150000,
  "internal_commuters": 105000,
  "in_commuters":       45000,
  "out_commuters":      55000
}
```

| 항목 | 어디서 |
|---|---|
| 상주인구 | KOSIS 인구주택총조사, 또는 행정안전부 주민등록 인구통계 |
| 거주 취업자 | KOSIS 지역별고용조사 → 시군구 취업자 |
| 관내 일자리 | KOSIS 전국사업체조사 → 시군구별 종사자수 |
| 통근 세 값 | KOSIS 인구주택총조사 → 통근통학인구. 거주지–근무지 교차표 하나에서 셋이 다 나온다 |

`peers` 에 다른 도시를 넣으면 같은 표에서 나란히 비교된다. 비교군은 대전·청주처럼
성격이 다른 기성 도시를 넣어야 세종의 자족성이 어디쯤인지 읽힌다.

**파일이 없어도 나머지 상황판은 정상 동작한다.** 그 블록만 `업데이트 예정` 으로 뜬다.
재료 여섯 개 중 일부만 채워도 만들 수 있는 지표는 만들고, 못 만든 지표는 무엇이
비었는지 화면에 적는다. 서식만 보고 싶으면 `config` 의 `selfsuff.use_example` 을
켠다(화면에 `표본값` 배지가 붙는다).

## 지도 자산

지도는 세 겹 모두 실제 좌표다. 자산 파일이 없으면 그 겹만 빠지고 나머지는 정상 동작한다.

| 자산 | 내용 | 만드는 법 |
|---|---|---|
| `assets/sejong_admin.json` | 행정동 20개 경계 + 시 외곽선 | `python tools/make_admin.py <행정동.geojson>` |
| `assets/sejong_rivers.json` | 하천수계 69개(금강·미호강·조천 등) | `python tools/make_rivers.py <osm.json>` |
| `assets/flood/` | 침수·범람도 오버레이 | `python tools/make_flood.py <범람.geojson> --type 외수 --freq 100년` |

각 도구의 docstring에 원본 자료를 받는 방법(주소·Overpass 질의문)이 적혀 있다.
하천망은 OpenStreetMap(ODbL) 자료이며 화면 하단에 출처를 표기한다.

### 침수·범람도 오버레이

`assets/flood/` 에 레이어를 등록하면 지도 위에 **빈도별 토글 버튼**이 생기고,
켜면 반투명 면으로 겹쳐 보인다. 외수(하천범람)는 주황, 내수(도시침수)는 보라가 기본색.

받을 곳:

- 홍수위험지도정보시스템 <https://www.floodmap.go.kr> — 하천범람(외수)
- 공공데이터포털 15141731 — 권역별 빈도별 도시침수지도 (내수, 30/50/80/100년)
- 공공데이터포털 15141734 — 행정구역별 빈도별 도시침수지도 (내수, 30/50/80/100년)

**좌표계 주의** — 국내 자료는 EPSG:5179/5186 로 오는 경우가 많다. `make_flood.py` 는
변환을 하지 않으므로 QGIS 등에서 **EPSG:4326(WGS84)** 으로 내보낸 뒤 넣어야 한다.
경위도 범위를 벗어나면 도구가 그 자리에서 걸러내고 알려준다.

```bash
C:/Python313/python.exe tools/make_flood.py --list
```

## 읽을 때 주의

- 수위·강수는 **보정 전 원시자료**다. 실제 홍수 대응 판단은 한강홍수통제소 공식 발표를 따를 것.
- 수질 등급은 하천 생활환경기준의 **TOC 항목만으로 산출한 참고값**이다.
  법정 등급은 여러 항목을 함께 보므로 이 화면의 등급을 그대로 인용하면 안 된다.
- 지하수위는 API가 표고(EL.m)로 주는지 지표하 심도(GL.m)로 주는지 기관마다 다르다.
  첫 수집 뒤 값의 스케일을 한 번 확인할 것.
- 수질 지점 필터(`nier.name_keywords`)에 걸리는 지점이 없으면 **비워두고 사유를 남긴다.**
  전국 지점으로 대신 채우지 않는다 — 화면은 멀쩡한데 내용이 틀리는 상황을 막기 위해서다.
- 약국·병의원의 '지금 문 연 곳'은 **기관이 신고한 진료시간으로 계산한 값**이다.
  임시 휴진과 공휴일 변경은 반영되지 않는다. 화면에도 그렇게 적어 두었으나,
  이 화면을 보고 헛걸음하는 일이 없도록 인용할 때도 함께 밝힐 것.
- 응급실 가용병상은 기관이 직접 입력한다. 입력이 밀리면 실제와 다를 수 있어
  관측시각을 병원마다 표시한다.
- 자족도시 지표의 구간 라벨(낮음·보통·높음, 균형)은 **참고선**이다. 영국 신도시 자족률과
  미국 직주균형 관행에서 가져온 값이지 법정 기준이 아니다. 인용할 때 구간이 아니라
  수치와 산식을 함께 밝힐 것.
- `--demo` 로 만든 화면은 상단에 `샘플 데이터` 배지가 붙는다. 배지가 있으면 실측이 아니다.
